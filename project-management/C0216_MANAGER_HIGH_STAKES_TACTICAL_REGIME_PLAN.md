# C0216 — Manager High-Stakes Tactical Regime (MHTR) — Deferred Research Plan

Status: **OPEN / PLANNED / DEFERRED**

Purpose: preserve the agreed design for later research and implementation. **Do not activate any production model effect from this plan without a separate forward-validation and promotion decision.**

## Core idea

Do not model a simplistic rule such as “Coach X normally plays 3-4-2-1 in derbies.”

Build a **Manager High-Stakes Tactical Regime Model** that estimates:

> Given this manager, opponent, stakes, competition structure, aggregate state, squad availability and incentive state, what tactical regime is the manager most likely to choose — and how does that regime change player roles, expected minutes, team attacking/defensive intensity and the shape of the score distribution?

The intended value is the **manager/context interaction** and the **deviation from the manager’s normal regime**, not a generic “big match” coefficient.

## High-stakes contexts to distinguish

Do not collapse all of these into one label:

- Derby
- Cup final
- Knockout first leg
- Knockout second leg
- Aggregate lead / aggregate deficit
- Must-win league match
- Draw-is-enough match
- Title/relegation six-pointer
- Elite-opponent fixture
- Protecting a lead
- Chasing a tie

For two-legged ties, current aggregate state and home/away leg context are first-class inputs.

For derbies, do not assume a universal derby effect. Treat derby response as manager/team/context specific and require evidence.

## Proposed model hierarchy

1. **Normal manager tactical prior**
2. **Opponent-strength/style adjustment**
3. **Match incentive/stakes regime**
4. **Competition / aggregate-state adjustment**
5. **Available personnel constraint**
6. **Predicted formation**
7. **Predicted actual player roles**
8. **Predicted substitution behaviour**
9. **Downstream FPL and betting effects**

Formation is only one feature. Actual player role is more important than the nominal formation label.

## Tactical features to capture

Where data permits, model or label:

- Fullback/wingback height

- Double-pivot probability

- Defensive block height

- Press aggression

- Player-role displacement
- Substitution timing
- Shape changes when leading / drawing / trailing

## Betting consumer

Potential pathway:

`manager regime -> team attacking/defensive intensity -> home/away lambda adjustments -> score-distribution / tail-shape adjustments -> 1X2 / BTTS / totals / correct-score evaluation`

Do not assume the effect should be a simple mean-goal shift. Two fixtures with similar mean lambdas may have different variance/tail structure if generated by different tactical regimes.

Potential betting outputs to evaluate:

- Expected goals by side
- 1X2 probabilities
- Draw probability
- Clean-sheet probabilities
- BTTS
- Totals
- Exact-score distribution
- Tail probabilities / high-score suppression or amplification

## FPL consumer

Potential pathway:

`manager regime -> predicted XI -> expected minutes -> predicted tactical player role -> player event rates -> FPL xPts distribution`

Potential player-level consequences:

- Attacking fullback becoming conservative
- Midfielder dropping into buildup
- Winger becoming primary transition outlet
- Striker receiving fewer touches but higher-value transition chances
- Usual starter sacrificed for a tactically safer profile
- Different early-substitution or late-game substitution risk
- Clean-sheet and defensive-contribution changes
- Goal/assist ceiling changes
- Captaincy haul-probability changes

Do **not** add a generic player “big-match coefficient.”

## Statistical design / anti-overfitting protection

Manager-specific samples will often be small. Use hierarchical shrinkage rather than raw manager averages:

`global high-stakes prior -> context-specific prior -> manager-specific deviation`

A manager with only a few comparable matches should stay close to the broader prior. A manager with substantial comparable evidence can earn a larger personalized deviation.

Additional rules:

- Match importance/incentive labels must be determined **pre-match**, never retrospectively from the result.
- Missing tactical evidence is NULL / unknown, never zero.
- Do not use one result, one formation switch, or one famous match as proof.
- Require multiple independent signals and at least one structural signal such as expected formation, expected role or expected minutes.
- Preserve strict chronology for all evaluation.
- Separate descriptive tactical accuracy from downstream predictive value.

## Recommended research sequence

### Phase 1 — Data/source audit

Before building a model, audit what historical data is genuinely available for:

- Manager identity and tenure
- Competition / round / knockout stage
- First-leg / second-leg status
- Aggregate score before kickoff
- Derby identification
- League table / title / relegation incentive state
- Starting formations
- Starting XI
- Realized player positions / roles
- Substitution timing and shape changes
- Team tactical metrics
- Match outcome and xG / shot process

Build a source/coverage matrix and identify chronology-safe historical availability.

### Phase 2 — Tactical-regime prediction test

First test whether MHTR can predict **observable tactical behaviour** better than the normal-match prior.

Primary targets:

- P(formation switch)
- P(back three vs back four)
- Fullback/wingback role
- Player-role displacement
- Starting-XI change
- Substitution timing
- Team attacking/defensive style shift

If the model cannot predict the tactical regime itself, do not allow it to modify xG, FPL xPts or betting distributions.

### Phase 3 — Downstream incremental-value test

Only after Phase 2 passes, evaluate whether the predicted regime adds stable incremental value to:

**Betting**
- xG / goal expectation
- Brier / log-loss for 1X2
- BTTS / totals
- exact-score likelihood
- calibration

**FPL**
- expected minutes
- start probability
- player role
- goal/assist/DC/clean-sheet probabilities
- xPts
- haul/blank probabilities

### Phase 4 — Shadow-only forward validation

Run as a separate **SHADOW** family first.

No production effect unless:

- Forward sample is complete enough
- Improvement is stable across reasonable assumptions
- Multiple proper-scoring metrics support it
- Gain survives model uncertainty
- Manager/context effects do not collapse when shrunk
- No hidden leakage from post-match labels
- Noise-Control concludes a meaningful edge exists

## Red-team risks

1. Tiny samples for specific managers/finals/derbies
2. Selection bias: only memorable high-stakes matches get labelled
3. Post-outcome leakage in “must-win” or pressure labels
4. Formation labels hiding very different actual roles
5. Manager changes and tactical evolution over time
6. Personnel availability confounding the apparent manager effect
7. Opponent strength/style confounding the stakes effect
8. Knockout aggregate state dominating a simplistic “final/derby” tag
9. Overlapping signals with existing tactical/role models causing double counting
10. Narrative overfitting: a plausible football story without measurable predictive lift

## Success criterion

The model is valuable only if it demonstrates a robust, chronology-safe, incremental predictive edge beyond our existing manager/team/role/tactical layers.

The desired generalization is:

> **Model what each manager does when the utility of a draw, lead, goal or elimination changes.**

This is broader and more useful than simply tagging finals or derbies.

**Save for later. Do not start model-family development now.**

When resumed, the first action is **Phase 1 data/source and architecture audit**, not coefficient fitting.
