# Football Intelligence Engine — Weekly Data Pipeline

_Last updated: 2026-09-07 — C0213 canonical operating pipeline_

## 1. Operating principle

The weekly pipeline is a chronology-safe state machine, not a single “run model” command. Projection readiness and decision readiness are intentionally separate.

Completed-match evidence may update future Gameweeks only. Fixture intelligence freezes at kickoff. Missing source fields remain missing. Registered forward cohorts remain immutable.

## 3. Three-Gameweek prospective state

The main upstream refreshes cover the first **three future Gameweeks** to support multi-GW FPL optimization.

| Cadence | Job | Output |
|---|---|---|
| 08:20 / 18:20 daily | `football_intelligence_role_tactical_refresh` | expected roles/tactical fixture state |
| every 4h, minute 30 | `football_intelligence_forward_forecast_refresh` | forward structural fixture forecasts |
| every 4h, minute 40 | `football_intelligence_forward_enriched_refresh` | enriched forward state |
| every 4h, minute 50 | `football_intelligence_feature_snapshot_refresh` | team feature snapshots |
| minutes 03/18/33/48 hourly | `c0159_production_fixture_refresh` | C0159 → C0166 production fixture cycle |

The current decision-grade fixture row must be generated by `production_fixture_v0.3_c0166`.

## 4. FPL projection cadence

`football_intelligence_fpl_upcoming_snapshot` runs every five minutes and calls `private.generate_upcoming_fpl_snapshot_v01()`.

The wrapper:

1. identifies the upcoming pre-deadline GW;
2. checks C0204 projection-universe coverage;
3. performs narrowly governed new-player reconciliation when eligible;
4. fails closed if ungoverned projection gaps remain;
5. calls the canonical projection core;
6. writes append-only player projections and point distributions;
7. writes an automated current-15 decision only if the decision gate permits it.

Historical forecasts are never rewritten.

## 5. End-of-Gameweek realization sequence

After the prior GW completes:

1. `sync-gw-results` must produce a final result run.
2. player actuals and team actuals are appended.
3. `ingest-realized-player-roles` maps completed-match tactical roles.
4. current player state refresh incorporates only completed-match evidence.
5. team state refresh incorporates current-season evidence.
6. role/tactical prospective state is rebuilt for future fixtures.
7. C0159/C0166 fixture forecasts refresh.
8. future FPL projections refresh.

A partial result run or incomplete realized-role mapping does not become zero/neutral evidence; it is a readiness blocker.

## 6. Full-pool optimizer orchestration

`football_intelligence_c0213_full_pool_optimizer` runs at minutes 12/27/42/57.

The optimizer is called only when `private.c0213_p2_horizon_readiness_v02(gw,3)` confirms a current three-GW input set.

The immutable optimizer signature includes:

- target GW;
- horizon;
- active model ID;
- exact prediction-run IDs;
- manager-state ID;
- free transfers;
- budget;
- transfer cost;
- bench leakage weight;
- model-error margin;
- horizon weights.

A later projection or manager-state refresh invalidates an older optimizer result for decision-grade use.

The Edge Function itself is read-only and cannot write a manager plan.

## 7. Manager state

Before a final future-GW decision, capture the actual manager state rather than inferring missing values as zero:

- current 15-player acquisition squad;
- bank;
- free transfers;
- acquisition squad cost;
- relevant chip state where applicable.

Missing manager state blocks the full-pool optimizer decision path.

## 8. Decision-readiness contract

`private.c0213_p2_current_lineage_v03(gw)` evaluates:

1. RESULTS
2. FPL_CURRENT_DATA
3. REALIZED_ROLES
4. PLAYER_STATE
5. TEAM_STATE
6. TACTICAL_FIXTURE_STATE
7. FIXTURE_PROJECTION
8. PLAYER_PROJECTION
9. POINT_DISTRIBUTION
10. MANAGER_STATE
11. FULL_POOL_OPTIMIZER
12. DECISION_READINESS
13. AUTOMATED_CURRENT15_DECISION
14. SAVED_MANAGER_PLAN

Final decision readiness requires all material upstream decision inputs to be current and green. A numerical projection can be valid while a final manager decision remains blocked.

Fail-closed write guards protect:

- automated `decision_snapshots` inserts;
- future `fpl_manager_plans` inserts.

## 9. Noise-Control / Decision-Control step

When readiness is green, the manager decision process still applies the project’s FPL operating rules:

- full available player pool, not only the current squad;
- top-xMins candidate pool plus explosive exceptions;
- expected-minutes and tactical-role gates;
- multi-signal requirement;
- whole-squad £100m reoptimization after every candidate move;
- opportunity cost and club-slot cost;
- transfer burden and future flexibility;
- bench leakage and formation flexibility;
- ownership/EO only as game-theory context, never as quality proof;
- captaincy optimized separately;
- compare every transfer against ROLL;
- if differences are inside model uncertainty → `NO_MEANINGFUL_EDGE`, no action.

Only the final adjudicated plan becomes the authoritative saved manager plan.

## 10. Forward research schedules

Research schedulers are independent of production decisioning:

- A0005 near-close capture every five minutes; evaluator four times per hour;
- W0002 near-close capture every five minutes; evaluator four times per hour;
- C0147 shadow capture every 15 minutes; evaluator hourly;
- C0197 shootout shadow every four hours;
- bookmaker capture/refresh on its own cadence.

Research schedulers may populate shadow/evaluation tables but cannot activate a production model effect.

## 11. Storage / lineage maintenance

- `football_intelligence_c0213_lineage_capture` — hourly minute 14;
- `football_intelligence_c0213_storage_retention` — daily 04:37.

Retention compaction preserves protected/frozen prediction and result lineage; it does not rewrite historical model outputs.

## 12. Required weekly verification

Before a meaningful FPL recommendation:

1. run `private.audit_change_tracker_governance_v01()`;
2. require `private.c0213_architecture_registry_status_v01()->system_consolidation_ok = true`;
3. inspect `private.c0213_p2_current_lineage_v03(target_gw)`;
4. require current three-GW projections/distributions;
5. require realized-role coverage/readiness;
6. require current manager state;
7. require exact-signature full-pool optimizer result;
8. verify injuries, press conferences, predicted/confirmed lineups, expected minutes, set pieces and congestion from current sources;
9. execute Noise-Control/Decision-Control;
10. save a manager plan only after all gates pass.
